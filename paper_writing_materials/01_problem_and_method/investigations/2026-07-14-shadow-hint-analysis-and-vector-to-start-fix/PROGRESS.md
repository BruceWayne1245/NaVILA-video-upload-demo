# 2026-07-14 — Fix: stop chaining raw ICP dtheta into the injected "vector to start" hint text, and a 50-episode two-batch live validation

**Context**: `FINDINGS.md` (this folder) traces ep367's return failure to `_anchor_progress_from_estimate()` composing the raw, per-attempt, un-fused `estimate.anchor_dtheta_rad` with the anchor's recorded `pose_from_start` to build the "next-anchor vector dx=.., dy=.." clause actually injected into the VLM's prompt (`hint_mode=compact`) — a straight-line (wall-blind) vector to the distant start, vulnerable to raw ICP rotation being confidently wrong by ~180° on symmetric corridors (this project's long-open "Mode 3"/rotational-aliasing signature). This composition is independent of the already-fixed belief-fusion mechanism (Variant 1, `sequential_pair_closure_check=False` this whole batch) and was never in scope of any prior bearing-accuracy validation, since all of that work measured `bearing_to_anchor_deg` (pure translation, no dtheta).

## What the hint text actually injects (compact mode, `_make_anchor_hint()`)

Three clauses, normally: (1) `route anchor A{X} is {d} m away, {bearing}` — current-anchor translation-only bearing, what `hint_action_arbiter` itself uses; (2) `estimated remaining route via anchor is {R} m` — a scalar, no direction; (3) `next-anchor vector dx=.., dy=..` — despite the name, this is `target_dx_m`/`target_dy_m`, which for the shadow (`anchor_relocalization`) path was the dtheta-composed beeline-to-start described above. A degraded "position uncertain / filter lost lock" variant replaces all three with a single qualitative direction word when `filter_std_m` crosses `_filter_lost`'s threshold.

For comparison, `direct_oracle_route_anchor_progress` (the oracle-driven hint generator) sets `target_dx_m`/`target_dy_m` **equal to** `anchor_dx_m`/`anchor_dy_m` — it always targets a nearby recorded waypoint anchor (not the distant start), so it never had this failure surface. This is a real, structural design difference between the two hint sources, not just an accuracy gap.

## Fix implemented

`route_memory_agent.py`, `_anchor_progress_from_estimate()`: removed the `relative_delta`/`compose_pose` chaining of `anchor_dtheta_rad` through `anchor.pose_from_start`. `target_dx_m`/`target_dy_m` (and therefore `bearing_to_start_deg`, and the injected hint text's third clause) now simply mirror `anchor_dx_m`/`anchor_dy_m` — the same convention `direct_oracle_route_anchor_progress` already uses. This is a complete fix for both problems identified in `FINDINGS.md` Part 8 at once: no more wall-blind beeline-to-distant-goal (the vector now points at a recently-confirmed nearby anchor, which by construction follows corridor turns), and no more dependence on raw `dtheta` at all (the injected hint's directional signal is now the same already-validated, translation-only ICP quantity `hint_action_arbiter` and the Part-2 ICP-accuracy analysis already trust, median ~2° excluding ep367).

**Consumers checked before changing** (`grep` across `round_trip_eval.py`/`hint_action_arbiter.py`/`stop_gate.py`): `_make_anchor_hint()` (the target); `stop_gate.py`'s `_bearing_to_command()` (only fires on a VETO decision — gets *safer* under this change, since it now steers toward the nearby anchor instead of potentially through a wall); `hint_action_arbiter.py`'s `target_dx`/`target_dy` fallback (only reached when `anchor_dx_m`/`anchor_dy_m` is `None`, which never happens on this path — confirmed inert); a couple of `shadow_alignment`-diagnostic-only fields (dead now that `route_hint_source=integrated` means there's no parallel oracle to diff against). No other consumer found.

**Validated**: `py_compile` clean. One existing unit test (`test_full_pose_anchor_uses_reliable_heading_to_chain_start_vector`) explicitly asserted the *old* composed-beeline behavior and failed as expected against the fix — rewritten as `test_full_pose_anchor_target_vector_mirrors_anchor_translation`, asserting `target_dx_m`/`target_dy_m` now equal `anchor_dx_m`/`anchor_dy_m` directly. Full suite (`tests/test_route_memory_agent.py` + `tests/test_geometry_pipeline.py`, 180 tests) re-run clean: 180 passed, 14 pre-existing skips, zero other regressions.
