# 2026-07-15 — Implemented and unit-tested: opt-in quality-based "next"-role quarantine using `icp_best_to_second_score_ratio`; live 22-episode validation launched

**Context**: `FINDINGS.md` (this folder) found that the existing quarantine mechanisms (`window`/`trend` modes) structurally cannot catch the confirmed failure pattern — current and next anchors going bad *simultaneously* — because both modes explicitly, by design, only ever judge "next" relative to the simultaneously-read "current" anchor, and never monitor "current" itself. Two candidate signals for a new, independent "next"-role gate were tested offline against this project's own 50-episode batch data: raw promotion-wait-time (attempt count) and promotion-vote pass-fraction. **Both were rejected — neither separated legitimate slow-but-fine anchors from genuinely-bad stuck ones at any threshold tested** (false-positive rate tracked true-positive rate almost 1:1 in both cases). A third signal, `icp_best_to_second_score_ratio` (how close the second-best-scoring ICP yaw-seed hypothesis is to the winning one, from that single attempt's own 24-seed sweep — a live, per-attempt, single-anchor ambiguity signal, independent of any cross-anchor comparison and independent of the simultaneously-read "current" anchor), was tested and found to separate the two populations far better: at threshold 0.75 (mean over a candidate's whole "next" dwell, after ≥5 samples), it catches 88.9% of known-bad stuck anchors at an 33.7% false-positive cost to legitimate slow anchors — a ~55-point gap, vs. ~0 for the two rejected signals.

## What was implemented

All changes are additive and off by default; existing behavior is byte-for-byte unchanged unless the new flag is explicitly passed.

- **`AnchorRelocalization.best_to_second_score_ratio: Optional[float] = None`** (`route_memory_agent.py`) — new field, mirroring how `match_class`/`near_tie_basin_count` were carried through on 2026-07-07.
- **`relocalization.py`**, `sequential_pair_anchor_relocalization()`'s `AnchorRelocalization(...)` construction — now also passes `best_to_second_score_ratio` from the already-computed `basin_metrics["best_to_second_score_ratio"]` (previously only written into the diagnostic `covisibility_records`, discarded for the live decision path).
- **`RouteMemoryAgent._record_next_anchor_quality()`** (new method, `route_memory_agent.py`) — for each estimate in the "next" role (never "current" — mirrors the existing quarantine modes' own current-role exemption, but for an independent reason: this signal doesn't need current to be trustworthy, so there was no reason to extend it to current in this first cut either), accumulates `best_to_second_score_ratio` into a per-anchor history; once `quarantine_next_quality_min_samples` (default 5) samples are observed, computes the mean and adds the anchor to the existing `_quarantined_anchor_indices` set (shared with the other two quarantine modes) if the mean exceeds `quarantine_next_quality_threshold` (default 0.75). Called from `update_relocalization()` alongside the existing `_record_next_anchor_stability()`, and is a fully independent, stacking check — does not read or modify anything the `window`/`trend` modes use.
- **`RouteMemoryAgent._next_candidate_index()`** — the skip-ahead-past-quarantined-anchors gate previously only checked `sequential_pair_quarantine_enabled`. Fixed to also check the new `quarantine_next_quality_enabled`, since the new mechanism populates the same `_quarantined_anchor_indices` set but is independently switched — without this, enabling only the new flag would quarantine anchors that never actually get skipped.
- **New CLI flags** (`round_trip_eval.py`): `--sequential_pair_quarantine_next_quality` (off by default), `--sequential_pair_quarantine_next_quality_threshold` (default 0.75), `--sequential_pair_quarantine_next_quality_min_samples` (default 5). Also logged into the measurement JSON's config-echo block for reproducibility.

## How to revert

Simply omit `--sequential_pair_quarantine_next_quality` from the launch command (the default is off). No other code path is touched when it's off — this was verified by running the full existing test suite (below) with zero regressions.

## Validation

7 new unit tests, `tests/test_route_memory_agent.py::SequentialPairNextQualityQuarantineTest`: default-off preserves behavior exactly; a persistently-ambiguous candidate (mean ratio 0.9, 5 samples) gets quarantined; a clearly-unambiguous one (ratio 0.3) does not; below-min-samples does not quarantine yet; the "current" role is never flagged regardless of its own ratio; a missing/`None` ratio (e.g. only one ICP basin found, no second hypothesis to compare) is never treated as a bad vote; and `_next_candidate_index`'s skip-ahead engages even when the *original* `sequential_pair_quarantine_enabled` flag is off. Full suite re-run: **187 tests (180 prior + 7 new), 14 pre-existing skips (unchanged), zero regressions.**
